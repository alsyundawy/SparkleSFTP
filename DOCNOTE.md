# DOCNOTE — SparkleSFTP Engineering & Architecture Notes

## 1. Project Lineage & Rebranding

**SparkleSFTP** evolved from the initial `MacSFTP` architecture specification. All documentation, SwiftPM targets, bundle identifiers (`com.alsyundawy.SparkleSFTP`), Keychain service namespaces, and `OSLog` subsystems are standardized as **SparkleSFTP**, incorporating all 55 findings from [`docs/CODE_REVIEW_14_PILLARS.md`](docs/CODE_REVIEW_14_PILLARS.md).

## 3. Build, Lint, and Test Commands

All commands run via `/usr/local/bin/bash -l` (bounded parallelism `-j 2`):

```bash

# Run Swift Testing suite under Command Line Tools macOS SDK
swift test -j 2 --disable-xctest --enable-swift-testing \
```

## 4. Known Scope Boundaries & Honest Capabilities

1. **SSH Private Key Formats**: `apple/swift-nio-ssh 0.15.1` natively signs with `ssh-ed25519`, `ecdsa-sha2-nistp256`, `ecdsa-sha2-nistp384`, `ecdsa-sha2-nistp521`, and Secure Enclave P-256 (`NIOSSHPrivateKey`). `PrivateKeyParser` parses unencrypted OpenSSH v1 Ed25519/ECDSA and PKCS#8 PEM keys cleanly and surfaces an explicit error for unsupported legacy RSA or encrypted keys pending RFC 8332 signer support.
2. **Loopback vs Docker Integration Tests**: An in-process encrypted loopback SSH/SFTP v3 + `DirectTCPIP` server suite (including `LoopbackSSHServer`, `TransferAndTerminalRegressionTests`, `TransferBatchAndPolicyTests`, `SecurityHardeningTests`, `FolderPermissionsTransferTests`, `ShellTabsAndWindowControlsTests`, `LoopbackTransferResumeTests`, `PreferencesAndDialogSizeTests`, `HardeningRegressionTests`, totaling `121 tests across 33 suites`) runs via `swift test --no-parallel` verifying real SFTP v3 framing, `64 KB` pipelined `512 KB` multi-chunk upload/download SHA-256 parity + sparse-hole-free pause/resume, `FTPService` Release lifetime safety & cancellation-safe `SFTPChannelBridge`/`SSHClientService` `runExec`, zero-prompt `FileHostTrustBackingStore` (`0600` JSON) + non-interactive `KeychainService`, independent Upload/Download 8-policy conflict resolution, `enqueueBatch`/`cancelAll`/`retryAllFailed`/`clearCompleted` + `TransferJournal` WAL batching, `CancellationError` zero-alert suppression & `NSMenuDelegate` menu guards, `StandaloneTerminalManager` + `TerminalSplitNode` multi-tab/split-pane/SSH sanitization, 1-tab-1-shell SSH binding & Quick Connect visibility, standalone window Close/Minimize/Zoom & `Esc`-safe sheet continuations, `CWE-22`/`CWE-78`/`CWE-88`/`CWE-409` defenses, Commander INI `FSProtocol` (`0=SCP, 1/2=SFTP`) & `0xA3` password decryption, `76` WCAG AA palettes, and `456`-key EN/ID parity without external containers. Multi-server Docker interop fixtures (`127.0.0.1`-bound) live in `Tools/TestServers/docker-compose.test.yml` and `Tools/TestServers/run-integration-tests.sh` for environments with Docker Engine running.
3. **macOS `.app` Bundling, CI Release & Notarization**: Running `swift run SparkleSFTP` launches the native SwiftUI + AppKit window cleanly (with Hardened Runtime direct-distribution `SparkleSFTP.entitlements` disabling App Sandbox so `LocalProcessTerminalView` login shells and Sparkle updates operate smoothly); `Tools/Release/build-universal.sh` copies `SparkleSFTP_*.bundle` resource bundles into `Contents/Resources/` (paired with crash-safe resolution in `LocalizationCatalog.resolveResourceBundle()` & `AppDelegate`), applies inside-out Sparkle signing, and together with `create-dmg.sh` (computing `.sha256` after signing) and `.github/workflows/release.yml`, produces the Universal 2 (`x86_64 arm64`) `.app` `v0.4.0` + `.dmg` + `.sha256` (`Tools/Release/notarize.sh` requires production Developer ID & notarization credentials). See [ADR-008](docs/ADR/0008-multi-window-isolation-appkit-tab-chrome-76-themes-and-transfer-pipeline.md) and [`docs/LONG_TERM_REVIEW_2026_11.md`](docs/LONG_TERM_REVIEW_2026_11.md) for the live 14-pillar hardening register, SonarQube `reports/swiftlint-sonarqube.json` pipeline, and 90-day / 12-month sustainability roadmap.
4. **Runaway CPU Elimination, FileZilla-Inspired Logging & High-Performance Table Reuse (`v0.3.0`)**: Resolved an infinite 100% CPU layout feedback loop in `SparkleWindowConfigurator` by replacing `NSWindow.didUpdateNotification` with `NSWindow.didResizeNotification`; implemented AppKit cell/row reuse (`tableView.makeView(withIdentifier:owner:)`) in `FilePaneTableView` for `ThemedFileRowView`; added 250ms debouncer in `LocalDirectoryWatcher` (`LocalFileService.swift`); introduced FileZilla-style real-time timestamped `[HH:mm:ss]` Activity Logging Console (`ActivityLogger`, `ActivityLogView`, `⌥⌘L`); added workspace tab disconnect and connect-in-new-tab options; clarified orthodox commander shortcut mappings (`F5` cross-pane transfer vs `⇧F5` Copy To... vs `⌘C` clipboard); added centered minimize/hide controls on transfer drawer and activity console; added modal `NSAlert` feedback for manual update checks; and modernized application icon assets (`AppIcon.png`, `AppIcon.icns`) with complete removal of solid black backgrounds in favor of an RGBA subpixel anti-aliased squircle.
5. **Cold-Launch Performance, Invalidation Decoupling, Transfer Throttling & Cross-Platform Resilience (`v0.4.0`)**:
   - **Lazy-Load Theme Catalogs**: Defer instantiating 74 built-in palettes and custom JSON disk scanning until `PreferencesThemeTab` is explicitly opened. At startup, `SparkleThemeStore.loadBootstrapPalettes` loads only the default light, default dark, and active user palette, drastically cutting cold-launch memory and CPU usage.
   - **SwiftUI View Invalidation Decoupling**: Extracted `MainWindowStatusBar` and `MainWindowMinimizedTransferBar` as self-contained subview structs, decoupling `MainWindowView` root body passes from high-frequency transfer progress notifications and status messages.
   - **Transfer Monitor Coalescing & Throttling**: Implemented an 80ms throttle window (~12.5 Hz, strictly within 10–15 Hz) in `TransferMonitor.updateSnapshots` and eliminated the `snapshots.count <= 20` bypass in `TransferQueue.broadcastSnapshots`, preventing render loop saturation during high-volume micro-file transfers while preserving `visibleLimit = 150` in `TransferQueueView`.
   - **Cross-Platform File Transfer Resilience (macOS <-> Linux/BSD)**: Handled POSIX `SSH_FXP_SETSTAT` `SSH_FX_PERMISSION_DENIED` errors as non-fatal warnings when preserving `mtime` and `chmod` permissions on Linux/BSD filesystems; automatically filtered macOS `.DS_Store` and AppleDouble `._*` metadata files during recursive uploads and synchronization scans; and switched in-progress uploads to `.destination.sparklesftp.<uuid>.filepart` temporary naming with atomic completion renames.
   - **Launch Profiling Signposts**: Added `OSSignposter` markers (`ThemeInitialization`, `InitialDirectoryListing`, `WindowConfiguration`) under subsystem `com.sparklesftp.app` / category `LaunchPerformance` for Time Profiler inspection in Xcode Instruments.
