# DOCNOTE — SparkleSFTP Engineering & Architecture Notes

## 1. Project Lineage & Rebranding

**SparkleSFTP** evolved from the initial `MacSFTP` architecture specification. All documentation, SwiftPM targets, bundle identifiers (`com.alsyundawy.SparkleSFTP`), Keychain service namespaces, and `OSLog` subsystems are standardized as **SparkleSFTP**, incorporating all 55 findings from [`docs/CODE_REVIEW_14_PILLARS.md`](docs/CODE_REVIEW_14_PILLARS.md).

## 3. Build, Lint, and Test Commands

All commands run via `/usr/local/bin/bash -l` (bounded parallelism `-j 2`):

```bash
# Build all SwiftPM modules and macOS executable
swift build -j 2

# Run Swift Testing suite under Command Line Tools macOS SDK
swift test -j 2 --disable-xctest --enable-swift-testing \
  -Xswiftc -F/Library/Developer/CommandLineTools/Library/Developer/Frameworks \
  -Xswiftc -Xfrontend -Xswiftc -disable-cross-import-overlays \
  -Xlinker -F/Library/Developer/CommandLineTools/Library/Developer/Frameworks \
  -Xlinker -rpath -Xlinker /Library/Developer/CommandLineTools/Library/Developer/Frameworks

# Run SwiftLint & SwiftFormat checks
swiftlint lint --strict
swiftformat --lint .

# Run Markdown, YAML, GitHub Actions, and ShellCheck hygiene checks
npx --yes markdownlint-cli2 "**/*.md" "#.build" "#DerivedData" "#node_modules" "#.trunk"
yamllint -c .yamllint.yml .
shellcheck -s bash Tools/**/*.sh
shfmt -d -i 2 -ci Tools/**/*.sh
actionlint
```

## 4. Known Scope Boundaries & Honest Capabilities

1. **SSH Private Key Formats**: `apple/swift-nio-ssh 0.15.1` natively signs with `ssh-ed25519`, `ecdsa-sha2-nistp256`, `ecdsa-sha2-nistp384`, `ecdsa-sha2-nistp521`, and Secure Enclave P-256 (`NIOSSHPrivateKey`). `PrivateKeyParser` parses unencrypted OpenSSH v1 Ed25519/ECDSA and PKCS#8 PEM keys cleanly and surfaces an explicit error for unsupported legacy RSA or encrypted keys pending RFC 8332 signer support.
2. **Loopback vs Docker Integration Tests**: An in-process encrypted loopback SSH/SFTP v3 + `DirectTCPIP` server suite (`LoopbackSSHServer` + `LoopbackSFTPIntegrationTests` + `LoopbackAdvancedIntegrationTests` + `ToolchainAndConflictTests` + `WindowTabsAndCommanderCommandsTests` + `WindowControlsAndShortcutsTests` + `FolderPermissionsTransferTests` + `ShellTabsAndWindowControlsTests` + `LoopbackTransferResumeTests` + `PreferencesAndDialogSizeTests`, totaling `95 tests across 25 suites`) runs via `swift test --no-parallel` verifying real SFTP v3 framing, `64 KB` pipelined `512 KB` multi-chunk upload/download SHA-256 parity + pause/resume without sparse holes, stall-decaying `TransferSpeedMeter`, bottom-up POSIX permission & dotfile folder transfer preservation (`0o555`/`0o755`), `100%` partial upload resume & Conflict `.skip` zero-byte cleanup, 1-tab-1-shell SSH binding & Quick Connect unconnected-only visibility, standalone `PreferencesWindowController` / `AboutWindowController` Close/Minimize/Zoom & fixed constant tab/modal dialog sizes, `F7`/`⌘⇧C`/`⌘⌥C`/`⌘↩`/`⌥↩` + `NSText` focus guards, `zlib`/`gzip` `CWE-409` codecs, independent multi-window `AppState` isolation, paired FileZilla/WinSCP multi-tab workspaces, `PathValidator.escapePOSIXSingleQuoted`, `.gz` compression/upload & opposite-pane comparison, `ToolchainInspector`, `ExternalTerminalLauncher` `CWE-78` sanitization, FileZilla conflict policies & FIFO queue auto-drain, password/Ed25519 auth, TOFU + MITM key rotation blocking, SOCKS5/HTTP proxy tunnels, `ProxyJump` bastion chains, `-L`/`-R` port forwarding, all `76` SparkNotePad/NotepadNext palettes WCAG AA + theme propagation, 7-tab About diagnostics, Remember Password Keychain lifecycle, `FTPService` credential prompts, JSON i18n coverage (`365` keys), FileZilla/WinSCP BOM & `0xA3` password importers, Notepad2 editor models, bidirectional sync, and connection row keys/cloning/batch deletion/performance invariants without external containers. Multi-server Docker interop fixtures are defined in `Tools/TestServers/docker-compose.test.yml` and `Tools/TestServers/run-integration-tests.sh` for environments with Docker Engine running.
3. **macOS `.app` Bundling, CI Release & Notarization**: Running `swift run SparkleSFTP` launches the native SwiftUI + AppKit window cleanly with a community GitHub Releases API check inside Preferences -> Auto-Update; `Tools/Release/build-universal.sh` copies `SparkleSFTP_*.bundle` resource bundles into `Contents/Resources/` (paired with crash-safe resolution in `LocalizationCatalog.resolveResourceBundle()` & `AppDelegate`) and, together with `create-dmg.sh` and `.github/workflows/release.yml`, produces the Universal 2 (`x86_64 arm64`) `.app` + `.dmg` + `.sha256` (`Tools/Release/notarize.sh` requires production Developer ID & notarization credentials, inside-out Sparkle signing, and Sandbox `-spks`/`-spki` mach-lookup entitlements). See [ADR-008](docs/ADR/0008-multi-window-isolation-appkit-tab-chrome-76-themes-and-transfer-pipeline.md) and [`docs/LONG_TERM_REVIEW_2026_11.md`](docs/LONG_TERM_REVIEW_2026_11.md) for the live `5c2c212` technical debt register, SonarQube `sonar.externalIssuesReportPaths` fix & CI server gap analysis, and 90-day / 12-month sustainability roadmap.
